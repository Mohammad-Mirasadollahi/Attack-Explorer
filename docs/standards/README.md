# Attack Explorer — Modular Documentation & Content Authoring Standard System (`MOD-00`)

> **Module ID**: `MOD-00` (Master Router & Architecture Index)  
> **Scope**: All Markdown Engineering Documents (`/docs/**`, `/seo-audit/**`), Redesign Backlog & Preserved Source Archives (`/docs/redesign-backlog/**`), Attack Scenario Definitions (`/modules/scenarios/**`), Step-by-Step Operational Guides (`/lib/step-guides/**`), Threat Intelligence & Attribution Registries (`/lib/attack-sources-and-legal.ts`, `/lib/threat-intel-service.ts`), SEO/GEO Metadata (`/lib/seo-metadata.ts`), and Workbench UI Copy (`/components/**`).  
> **Status**: Mandatory Permanent Standard · **Supreme Active Production Workflow**: **`MOD-17`** ([Bespoke Studio Redesign Pipeline, Clean-Slate Rebuild & Quality Gates](./17-bespoke-studio-redesign-pipeline-and-clean-slate-standard.md)) · **Master Sidebar Queue**: [`/docs/redesign-backlog/MASTER-BACKLOG-SIDEBAR-ORDER.md`](../redesign-backlog/MASTER-BACKLOG-SIDEBAR-ORDER.md) · Enforced by `/lib/documentation-standards.ts` and `/lib/documentation-standards.test.ts` for `MOD-00` through `MOD-12`, and by `/lib/technical-clips.test.ts` and `/lib/section-3d-registry.test.ts` for `MOD-13` through `MOD-15`.

### Domain layout (engineering rule)

| Layer | Path | Responsibility |
| :--- | :--- | :--- |
| **Domain packages** | `/modules/scenarios/<id>/` | One bespoke folder per attack (`process-hollowing` benchmark). Required: merged `index.ts` (`scenario` + `stepGuide`), `choreography.ts`, `three/`, bespoke `excalidraw/`, bespoke 2D silent-lecture clips (`MOD-17`) |
| **Authoring contracts** | `/modules/scenarios/contracts.ts` | Step-guide and standard-patch types. Packages import these, not `lib/` |
| **Catalog** | `/modules/scenarios/all-*.ts` | Generated by `npm run scenarios:registry`. Do not edit by hand |
| **Legacy drafts** | `/modules/scenarios/legacy/` | Deprecated draft schema normalizer (scheduled for removal in Phase 1 Clean-Slate Purge per `MOD-17`) |
| **3D entries** | `/modules/scenarios/three-registry.ts` | Lazy dynamic `import()` loaders so only the active scenario's bespoke engine mounts |
| **App routes** | `/app/scenarios/[id]/` | Next.js pages only |
| **Workbench projection** | `/lib/scenario-step-guides.ts` | Binds domain guides to diagram and simulation engines |
| **UI** | `/components/` | React surfaces. Shared playback chrome only (`/components/three/`, `/components/technical-clip/`, `/components/excalidraw/`) |

Import domain code as `@/modules/scenarios/...`. `npm run scenarios:registry` refreshes barrels. The architecture test rejects removed compatibility folders, domain imports of app libraries, and hand-edited catalogs.

## 1. Why Our Documentation Standard Is Modular

Because **Attack Explorer** unifies interactive 2D network diagrams, kernel/process memory maps, raw SIEM/Sysmon telemetry, 3-layer pedagogical narratives, bespoke cel-shaded 3D cinema worlds, bespoke 2D silent lectures, bespoke Excalidraw chalk whiteboards, multi-vendor threat intelligence citations, and programmatic SEO/GEO structured data, **a single monolithic style guide cannot govern every artifact effectively**.

Instead, the Attack Explorer Documentation & Content Authoring Standard is architected as **specialized, composable modules (`MOD-01` through `MOD-18`)**, governed at the top by **`MOD-17` (Bespoke Studio Redesign Pipeline, Clean-Slate Rebuild & Quality Gates)** and **`MOD-18` (Per-Section Standalone 3D Diorama & Dedicated Engine Standard)**, and sequenced by the **Sidebar Master Backlog**.

## 5. Programmatic Enforcement & Universal Per-Section Clarity Law (`/lib/documentation-standards.ts`)

Every rule in `MOD-01` through `MOD-12` is backed by executable contracts in [`/lib/documentation-standards.ts`](../../lib/documentation-standards.ts) and [`/lib/section-3d-registry.ts`](../../lib/section-3d-registry.ts), and verified automatically by [`/lib/documentation-standards.test.ts`](../../lib/documentation-standards.test.ts), [`/lib/section-3d-registry.test.ts`](../../lib/section-3d-registry.test.ts), [`/lib/technical-clips.test.ts`](../../lib/technical-clips.test.ts), [`/lib/scenario-step-guides.test.ts`](../../lib/scenario-step-guides.test.ts), and [`/lib/inspector-scope.test.ts`](../../lib/inspector-scope.test.ts). Under **`MOD-17`**, the legacy artificial-diversity test (`/lib/scenario-cinematic-uniqueness.test.ts`, which enforced the retired 28-place template matrix) is slated for retirement during Phase 1 Clean-Slate Code Cleanup and replaced by bespoke per-scenario `choreography.test.ts` + real-browser **Director's Review** gates.

**Permanent Universal Per-Section Clarity & Studio Craft Laws**:
1. **Studio Bespoke Law (`MOD-17`)**: Strictly **one scenario per turn** in exact Sidebar order. Every episode must pass the **Mute Test**, **Swap Test**, **User-Approved Director's Blueprint**, **100% Bespoke 3D/2D/Whiteboard implementation**, and **Frame-by-Frame Browser Director's Review**—matching or exceeding `process-hollowing`.
2. **Prop-Purpose Clarity (`validateStoryPropClarity`)**: Whenever a Story Analogy introduces key props or paired objects (such as *"two golden master keys"*), both the Story prose and `storyMappings[]` must explicitly state what **each** prop unlocks or does—with zero technical jargon in Story text.
3. **Per-Token Inline Plain-English Why (`validateTechnicalSectionInlineClarity`)**: Across **Step and Memory deep-dive** technical blocks (`steps[].simpleExplanation`, `steps[].howItWorksInPractice`, `stages[].description`, and Sequence `underTheHood`), every technical API, syscall, kernel struct, hex flag, handle, or Event ID must carry an immediate plain-English parenthetical explaining **what it is and why it is used**. Overview `briefing.plainSummary` is a **roadmap** (`MOD-11` Formula A2), not a Step-level API dump.
4. **Overview Ownership & Inspector Shell (`MOD-12`)**: Cascading Process → Process Hierarchy; VAD → Memory; Stage Filter off Overview; sidebar labels without `(N)` counts; Steps without Auto-Play / legend cards; code under `/components/inspector/**`.
5. **1-to-1 Physical Mechanism Law (`MOD-16`)**: Never recycle generic rooms, vehicles, or metaphors across unrelated attacks; every physical prop and motion must literally execute the vulnerability's real mechanism.
6. **One-Stop Section Gate (`validateSectionFullClarityStandard`)**: Automatically enforced by `validateScenarioAgainstModularStandards()` for every Step/Memory section so prose clarity never regresses.
7. **Per-Section Standalone 3D Law (`MOD-18`)**: Every Step (`step-1..N`) and `memory-forensics` 3D scene MUST be an independent diorama with its own dedicated room/set, `>= 2` exclusive articulated props, independent 3-phase choreography engine (`choreography.ts`), working Cutaway, and 4 custom camera presets—never a cropped/sliced Overview station or trivial `Math.sin` idle loop.
